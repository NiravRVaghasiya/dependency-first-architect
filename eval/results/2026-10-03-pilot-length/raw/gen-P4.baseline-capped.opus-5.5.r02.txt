Safety and Guardrails\n\n- **Prompt injection:** treat issue text, comments, and repository content as untrusted data. Wrap them in delimiters, never follow instructions found inside them, and check proposed actions against a deterministic policy layer *outside* the LLM. Running in the sandbox limits the damage even if the agent is manipulated.\n- **Spam and abuse:** apply rate limits per reporter. Throttle new accounts more heavily, and don't let them trigger expensive fix runs automatically.\n- **Budgets:** set token, time, and compute caps per issue, per day, and per repo. A circuit breaker stops the agent if the failure rate spikes.\n- **Tone:** use comment templates plus LLM wording, limit the agent to one bot comment per state change, and don't make promises about timelines.\n- **Kill switch:** a repo-level config flag and a `/agent stop` command pause the agent immediately.\n- **Human override:** maintainer labels such as `agent-skip` and `agent-go` override the agent's judgment.\n\n---\n\n## 6. Human Interaction Model\n\n- **ChatOps commands:** `/agent triage`, `/agent fix`, `/agent retry`, `/agent explain`, `/agent stop`.\n- **Escalation rules:** escalate on low confidence, security signals, reproduction failures, failed iteration budgets, or reviewer disagreement. Escalation posts a summary and pings the owner.\n- **Dashboard:** shows the issue pipeline, costs, acceptance rates, and items waiting on humans.\n\n---\n\n## 7. Evaluation Strategy\n\n1. **Offline benchmark:** replay historical issues against the commit just before the real fix. Compare the agent's labels with the actual labels, and compare its fixes against the hidden real tests, in the style of SWE-bench. Run this on every prompt or model change.\n2. **Shadow mode:** the agent triages and fixes privately, with output going to an internal channel only.
