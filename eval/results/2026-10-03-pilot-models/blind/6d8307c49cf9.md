## 5. Phases

### Phase 1: Conflict Resolution Model + Persistence (Unlocks scaling & features)

**Depends on:** Phase 0 (V0 passes).

**Unlocks:** Phases 2–3 (scale, resilience, external exposure).

**Tasks (ordered by impact):**

1. **V1: Spike and load-test both conflict models** (OT vs CRDT).
   - Build minimal OT merge function (e.g., simple string insert/delete) and minimal CRDT (e.g., Yjs or Automerge stub).
   - Synthetic load: 8 concurrent clients, 100 edits/sec, 5 min run.
   - Measure: merge latency p95, CPU, memory, correctness (verify both branches converge).
   - Pass bar: OT <5ms merge latency, CRDT <50ms, both converge 100% of trials.
   - Decide: OT if latency acceptable; CRDT if offline required (currently not).
   - **Evidence:** Load test report (CSV + plot), commit hash of spike code, decision log.

2. **Hardened op-log schema** (after V1 passes, conflict model chosen).
   - Define `operations` table: `(op_id UUID, doc_id UUID, user_id UUID, timestamp, op_type, op_data JSON, version INT, checksum)`.
   - Version field is lamport clock (OT) or (version, client_id) pair (CRDT).
   - Checksum ensures no silent corruption.
   - Document table: `(doc_id UUID, name TEXT, created_at, created_by, last_op_version)`.

3. **Replication and persistence layer:**
   - Postgres: ops and documents tables, append-only ops, snapshots every 100 ops (to avoid full replay).
   - Snapshot table: `(snapshot_id UUID, doc_id, version, content_json, created_at)`.
   - Write all ops to DB before broadcasting.
   - On client reconnect: fetch ops since client's last_known_version, replay locally.

4. **Chosen merge library integration:**
   - Vendor OT library (e.g., ot.js) or CRDT (e.g., Yjs).
   - Wrap in service: `applyOp(doc_state, new_op) → merged_state`.
   - Unit tests: 20+ scenarios (insert/delete/concurrent, boundary cases).

5. **Observability hardening (Phase 0 logging + Phase 1 additions):**
   - Structured JSON logs: timestamp, trace_id, level, message, doc_id, op_id, user_id.
   - Metrics: ops/sec (counter), merge latency (histogram), op_log size (gauge).
   - Error: any merge divergence → log + alert.

6. **Feature flag for Phase 1 logic:**
   - Route new edits through OT/CRDT merge; old clients still work via Phase 0 last-write-wins (flag: `useConflictResolution`).
   - Canary: 10% of internal users → 100% after 3 days if no errors.

**Rollback:** Feature flag to Phase 0 (last-write-wins); ops logged in phase 0 format still readable.

**Exit check:**
- ✓ V1 passed (conflict model chosen).
- ✓ Ops and snapshots tables created, 1000+ ops persisted without error.
- ✓ Client reconnect fetches ops and rebuilds doc state correctly (test with network partition).
- ✓ Merge latency p99 <100ms under 50 ops/sec load.
- ✓ Feature flag canary: zero divergence errors over 3 days.
