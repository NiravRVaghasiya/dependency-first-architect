# Customer-Support RAG Chatbot Plan

I don't know your stack, doc volume, or support channels yet, so this plan makes assumptions, listed at the end. Please correct them.

## 1. Goals and success metrics
- **Primary goal:** deflect routine tickets with accurate, cited answers, and hand off cleanly when the bot can't answer.
- **Metrics to set up front:**
  - Resolution or deflection rate
  - Answer correctness (human-graded sample)
  - Groundedness (share of claims supported by retrieved text)
  - Escalation rate and CSAT
  - p95 latency (target under 4 s to first token)
  - Cost per conversation

## 2. Content ingestion
- **Sources:** help-center articles (Zendesk, Intercom, Help Scout, or a static site), plus optionally release notes, status-page FAQs, and macros from resolved tickets (after review).
- **Pipeline:** crawl or API export → clean HTML to Markdown → preserve headings, tables, and code blocks → attach metadata.
- **Metadata per chunk:** article URL, title, section path, product or plan, locale, last-updated date, and audience (admin or end user).
- **Sync:** webhook or nightly incremental re-index. Deletions must propagate, or the bot will cite retired articles.
- **Chunking:** split by heading structure, about 300–600 tokens, with the title and breadcrumb prepended to each chunk. Keep step-by-step procedures together.

## 3. Retrieval
- **Hybrid search:** BM25 plus dense embeddings, merged with reciprocal rank fusion. Keyword search matters for error codes and feature names.
- **Reranker:** a cross-encoder over the top 30–50 results, keeping the top 5–8.
- **Query handling:** rewrite follow-ups into standalone queries using chat history. Detect language and route to the matching locale.
- **Filters:** filter by product, plan, or version when the user's account context is known.
- **Store:** pgvector, if you already run Postgres, is enough for most help centers. Use Qdrant, Weaviate, or OpenSearch if you need scale or built-in hybrid search.

## 4. Generation
- **Prompt rules:**
  - Answer only from the provided context.
  - Cite article links.
  - Say "I don't know" when the context is insufficient.
  - Ask one clarifying question when the request is ambiguous.
  - Use the brand's tone.
- **Output:** a short answer, steps if relevant, and 1–3 source links.
- **Guardrails:**
  - Refuse or escalate for billing disputes, legal, security incidents, and account-specific actions.
  - Resist prompt injection, since docs and user input are untrusted.
  - Redact PII in logs.
- **Confidence gate:** if the top rerank score is below a threshold, don't answer. Offer handoff or suggest related articles.

## 5. Handoff and integration
- **Channels:** web widget first, then in-app and email drafts. Slack or Teams can come later.
- **Handoff:** create a ticket with the conversation transcript, retrieved articles, and the bot's attempted answer, so the customer doesn't repeat themselves.
- **Agent assist (phase 2):** the same pipeline suggests draft replies to human agents. This is lower risk and builds trust.
- **Actions (later):** authenticated tools such as order status, each with explicit permissions and confirmation.

## 6. Evaluation
- **Golden set:** 150–300 real questions from past tickets and search logs. Each has a reference answer and the correct source articles. Include unanswerable and adversarial questions.
- **Retrieval metrics:** recall@k and MRR.
- **Generation metrics:** LLM-as-judge for correctness and groundedness, calibrated against human review.
- **Regression gate:** run the suite in CI on any change to the prompt, chunking, embedding model, or LLM.
- **Online:** thumbs up/down, "did this solve it?", and weekly review of failed and escalated conversations.

## 7. Operations
- **Observability:** trace each request (query, rewrite, retrieved chunks, scores, answer, latency, tokens). Tools like Langfuse or LangSmith work.
- **Content feedback loop:** report unanswered questions and low-confidence topics to the docs team as a gap list. This is often the biggest payoff.
- **Security and privacy:** tenant isolation if there is private content, data retention limits, and a vendor DPA review.
- **Cost control:** cache frequent questions, use a smaller model for query rewriting, and cap context size.

## 8. Phased rollout
| Phase | Duration | Deliverable |
|---|---|---|
| 0. Discovery | 1 week | Confirm sources, metrics, and ticket-topic analysis. Build the golden set. |
| 1. Prototype | 2 weeks | Ingestion, hybrid retrieval, basic answers with citations. Offline eval baseline. |
| 2. Internal pilot | 2–3 weeks | Agent-assist mode, tuned retrieval, guardrails, and the confidence gate. |
| 3. Limited launch | 2–4 weeks | Web widget for 10–20% of traffic, handoff flow, dashboards. |
| 4. Full rollout and iteration | Ongoing | More channels, locales, and actions. Content-gap reporting. |

## 9. Key risks
- **Stale or conflicting docs:** mitigate with sync, "last updated" metadata, and a docs-gap workflow.
- **Hallucinated answers:** mitigate with strict grounding, the confidence gate, and citations.
- **Over-deflection:** make human handoff always one click away.
- **Multi-product or version confusion:** mitigate with metadata filters and clarifying questions.
