# Plan: Autonomous GitHub Issue Triage & Resolution Agent

## 1. Classification and Constraints

**System type:** AI/agentic (autonomous agent + human-in-the-loop gating)  
**Scope:** Greenfield  
**Scale:** Small (single team to start, one repository pilot, no external customers on day zero, non-regulated data)  
**Dominant constraint:** Safety (correctness of triage and hard boundary on what the agent can close autonomously)  
**One worst-case failure:** Agent auto-closes a critical security bug, losing visibility; or misclassifies a priority issue so developers miss SLA  
**Dominant risk:** Prompt injection / adversarial issue text causing incorrect actions or token drain  

**Budgets (labeled):**
- **AI inference cost per issue:** ASSUMPTION: $0.01–$0.05 per triage + $0.02–$0.10 per resolution attempt (GPT-4o or similar), validated against actual GitHub issue volume (Phase 2)
- **Latency:** ASSUMPTION: 2–5 sec end-to-end per issue in triage mode; <10 sec if invoking tool (label, comment); hard cap 30 sec before webhook times out
- **Availability/SLO:** ASSUMPTION: Best-effort (no uptime SLO); agent failure does not block human workflow (silent degradation acceptable initially, escalates to ops on Phase 3)
- **Human approval overhead:** REQUIREMENT: <10% of issues require human override (backlog review only; auto-close on very high confidence); validated in Phase 2 before hardening Phase 3

**Missing inputs that would shift planning (ask now or defer):**
1. **GitHub organization policy on auto-close:** Does org allow any agent-driven issue closure? If not, agent can only label+comment, triaging only (shifts Phase 3 from resolution to humans). → *Assume yes for scoping; escalate if no.*
2. **Acceptable issue categories:** Which issue types can agent safely close? (e.g., duplicates, invalid, wontfix, spam only?) → *Captured in Phase 1b decision gate V1.*
3. **Fallback authority:** Who approves agent labels and comments before they appear? Batch approval or real-time? → *Phase 1b; Phase 3 depends on this.*

**Exception candidates:**  
- None declared upfront; Phase 0 will likely reveal need for a feasibility spike on GitHub API rate limits + prompt injection surface if org policy unclear.

## 4. First end-to-end slice (Phase 0)

**Real request path:**  
1. GitHub issue opened or reopened → webhook fires → agent receives JSON payload (issue title, body, labels, author, URL).  
2. Agent reads issue text → calls inference endpoint (Claude 3.5 Sonnet) with prompt: "Classify this GitHub issue into: bug, feature-request, documentation, question, duplicate, spam, invalid, wontfix. Respond with JSON: {category, confidence, reason}."  
3. Agent applies label(s) based on category (e.g., "type: bug"); posts comment: "Triage: classified as [category] (confidence [%]); [reason]. Assigned to [team] for review." (or escalates if confidence <70%).  
4. Response logged to stdout as JSON event: {timestamp, issue_id, category, confidence, labels_applied, tokens_used, cost_usd, latency_sec}.  
5. Deployed: agent runs as a GitHub App with webhook receiver on HTTP endpoint (localhost:8000 for Phase 0; behind firewall or ngrok tunnel).  
6. Rolled back: disable webhook, labels/comments remain (safe), revert code in-place.  

**Who can reach it:**  
- Phase 0: **Internal testing only** – one private test repository, add 2–3 test issues manually (not from external users). Webhook allowlisted to internal IP or ngrok authtok.  

**Why it is read-only / scaffolded:**  
- Agent does NOT close, reassign, or delete issues in Phase 0 (read-only on mutations).  
- Inference endpoint is on a test API key with $5 daily cap + 1,000 req/day rate limit (prevent runaway cost if bug loops).  
- Token cap 1,000 output per issue (hard stop).  

**Exit check V0:**  
One real issue flows end-to-end:  
- ✓ Webhook fires, payload reaches agent  
- ✓ Agent classifies issue and posts a label + comment  
- ✓ Log entry appears in stdout with cost/latency/confidence recorded  
- ✓ No prompt-injection test issue succeeds (agent refuses and escalates)  
- ✓ Deploy succeeds via GitHub Actions; rollback (disable webhook, revert code) succeeds within 5 min  
- ✓ Injected failure (kill inference endpoint) is visible in logs within 10 sec; alert fires  
- ✓ Baseline metrics recorded: 0-load latency (first issue, cold inference): ~2–3 sec; cost per issue: $0.01–$0.03
