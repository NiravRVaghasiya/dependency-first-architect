## 4. First end-to-end slice (Phase 0)

**One real request, every tier:**

1. **User input:** Support agent or internal user submits a query: "How do I reset my password?" via REST API POST `/chat`.
2. **Input sanitization:** Trim, deduplicate whitespace, check length <500 chars, strip code blocks, prepend `[USER QUERY]` marker.
3. **Embedding:** Convert query to embedding (OpenAI text-embedding-3-small or similar).
4. **Retrieval:** Query vector DB (Chroma, local, for Phase 0) with embedding; return top-3 docs, scores.
5. **Prompt construction:** Insert query + retrieved docs into system prompt (opaque, no echo-back).
6. **LLM call:** Send to hosted API (OpenAI GPT-4o-mini) with hard token cap (1500 out); enforce timeout (30s, fail closed).
7. **Response construction:** Extract text, append doc source URLs, set confidence (avg similarity score).
8. **Confidence gate:** If confidence <0.6, flag "low confidence" and suggest human escalation.
9. **Output:** Return JSON: `{answer, sources: [{title, url}], confidence, escalated: bool}`.
10. **Logging:** Log query, embedding time, retrieval latency, LLM latency, response, cost, errors. Tag with request UUID.
11. **Monitoring:** Emit latency and cost metrics (Prometheus or CloudWatch); alert if p95 latency >5s or daily cost >$50 (baseline).
12. **Deployment:** Docker image pushed to registry; Kubernetes pod on staging cluster (or local for Phase 0). Helm chart or CloudFormation template for reproducibility.
13. **Rollback:** Pod drain, old image revert, immediate re-deploy (manual in Phase 0; CD pipeline in Phase 1+).

## 7. Cross-Cutting Concerns

- **Observability:** Add metrics dashboard (Prometheus/Grafana or CloudWatch): query volume, latency percentiles, cost per day, hallucination rate (weekly manual sample). Alerts: latency p95 >3s, daily cost >$50, ingestion errors. SLO dashboard: track p99 latency vs. 5s target.
- **Reproducibility:** Ingestion pipeline as code (Python script with parameters: doc source, chunk size, embedding model). Runbook for re-ingesting on schedule or on-demand. Version vector DB schema + doc IDs (tag snapshots, e.g., `v2024-10-03`).
- **Resilience:** Idempotent ingestion (if chunk already in DB, skip; use doc_id + chunk_index as key). Fallback vector DB (if primary is unavailable, query returns "data temporarily unavailable; please escalate"). Monitor ingestion lag (if docs not synced in 24h, alert).

### Phase 2
- **Security:** Prompt testing (injection payload suite, regression tests in CI). Feedback data sanitization (remove customer names/emails from thumbs-down reasons before storing). Audit log: who reviewed what, when (for legal hold if needed).
- **Observability:** Track confidence threshold and escalation rate per query type. Dashboard: "Why are queries escalating?" (histogram: low confidence, out-of-scope, error, other). Weekly report to support leadership.
- **Reproducibility:** Test suite for prompt injection (committed to repo, run in CI on every deploy). Feedback collection script (reproducible export of staging data). Known-issue registry (e.g., "chatbot does not handle billing questions; redirect to support").
- **Resilience:** Graceful degradation if LLM is slow (start with timeout 30s, fall back to "please escalate" after 5s). Multi-LLM fallback option (e.g., if OpenAI slow, try Claude; requires abstraction layer, optional for Phase 2).

### Phase 3
- **Security:** PII sanitization in customer input (strip email, phone, account IDs before passing to LLM). Redact from logs (logs may be retained for audit). Feature flag ensures only 10% of traffic sees chatbot (impact limited). Legal sign-off before production exposure.
- **Observability:** Canary metrics exposed in public dashboards (% of support tickets routed to chatbot, CSAT, escalation rate). Incidents logged with on-call pager integration. Customer feedback loop visible to support team (thumbs-up/down counts per query topic).
- **Reproducibility:** Staging mirrors prod (same vector DB, LLM endpoint, feature flag values). Runbook for canary progression (manual approval to 50%, then 100%). Rollback procedure documented and tested.
- **Resilience:** Circuit breaker triggers feature flag off if error rate >1% or latency >5s sustained. Manual intervention: if off-nominal behavior, support lead can flip flag. Escalation queue never drops queries (if chatbot fails, escalate to human; no data loss).

### Phase 4
- **Security:** Production PII redaction enforced (logs do not contain customer identifiers). Audit trail for doc updates (who changed what, when). Regular security scan of vector DB (no exposed credentials in indexed docs).
- **Observability:** SLO dashboard (latency, uptime, error rate vs. targets). Cost tracking (daily, weekly, monthly spend vs. budget). Public-facing status page (if support team uses it): "Chat assistant status: ✅ operational" or ⚠️ degraded. Anomaly detection (if queries spike 10x in an hour, alert; may indicate abuse or legitimate surge).
- **Reproducibility:** Infrastructure as code (prod deployment matches staging). Disaster recovery plan: if vector DB corrupted, restore from backup (retention: 30 days). Runbook for emergency patching (e.g., if LLM API breaks, hotfix prompt and redeploy in <30 min).
- **Resilience:** Multi-region failover (optional, depends on budget; Phase 4 baseline is single-region with graceful degrade). Async fallback: if response latency >5s, queue for async processing; respond to user with "We're working on your request; check back in 2 min." Session replayability (store request + response for audit; support team can replay if needed).

### Phase 5
- **Security:** Ongoing doc audit (monthly: are outdated docs still indexed? Remove if stale). Prompt drift detection (if LLM output deviates from learned style, alert).
- **Observability:** Deep-dive analytics (by topic, by doc, by user segment if applicable). Feedback-driven roadmap (top 10 unresolved issues ranked by frequency). Cost optimization tracking (reduction % vs. Phase 4 baseline).
- **Reproducibility:** Model evaluation suite (benchmark new models vs. incumbent on standard test set before promotion). Prompt A/B testing framework (if testing new prompt version, run on 5% of traffic, measure impact).
- **Resilience:** Chaos engineering (inject LLM latency or errors; confirm fallback works). Load testing (5x expected traffic; confirm latency and cost scale linearly). Dependency refresh (update embedding model, vector DB version, LLM API SDK quarterly or when security patches available).

## Key Risks & Mitigations

1. **Hallucination**: Phase 1 V2 gate validates <5% on held-out set. Phase 2 adds confidence thresholding. Phase 3 V3 measures customer satisfaction. Escalation fallback ensures humans review low-confidence answers.

2. **Cost runaway**: Hard token cap (1500 out) + cost budget in V1 + daily spend alerts (<$50/day) + monthly tracking (<$1.5k/month) + optional model downgrade in Phase 5. Phase 0 baseline ensures early visibility.

3. **Latency**: P99 <5s validated in V1 + measured in Phase 3 canary. Timeouts + circuit breaker prevent stalls. Optional async fallback in Phase 4.

4. **Data privacy / PII leakage**: Redaction in Phase 1 ingestion + input sanitization in Phase 0 + log sanitization (remove identifiers) in Phase 4 + legal sign-off before Phase 3 exposure.

5. **Customer dissatisfaction**: Phase 2 staging feedback + Phase 3 V3 CSAT gate ensures only high-quality experiences reach 100% of users. Confidence threshold + escalation provide human fallback.

6. **Dependency on LLM API**: Circuit breaker + fallback to manual support (feature flag). Optional multi-LLM routing in Phase 5 if needed.
