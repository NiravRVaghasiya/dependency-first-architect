# Plan: `exifrename`, a CLI that renames photos by their EXIF capture date

## 1. Goals and non-goals

**Goals**
- Rename every photo in a folder to a name built from its capture date, e.g. `2024-07-14_18-32-05.jpg`.
- Be safe by default: preview changes before applying them, never overwrite a file, and make every run reversible.
- Handle the formats people actually have: JPEG, HEIC, PNG, and common RAW formats (CR2, CR3, NEF, ARW, DNG).
- Give predictable output that scripts can rely on.

**Non-goals (v1)**
- Moving files into date-based folders (planned for v2 as `--into "{YYYY}/{MM}"`).
- Editing EXIF metadata.
- A GUI.

## 2. Command-line interface

```
exifrename [OPTIONS] PATH

Options:
  -n, --dry-run            Show planned renames without applying them (default)
  -y, --apply              Actually perform the renames
  -r, --recursive          Include subfolders
  -f, --format TEMPLATE    Filename template (default "{date:%Y-%m-%d_%H-%M-%S}")
      --fallback MODE      What to do when EXIF has no date: skip | mtime | filename  (default: skip)
      --tz-offset ±HH:MM   Shift times (e.g. a camera clock set to the wrong zone)
      --ext LIST           Extensions to process (default: jpg,jpeg,heic,png,cr2,cr3,nef,arw,dng)
      --lowercase-ext      Normalize extensions to lowercase
      --no-sidecars        Don't rename matching .xmp/.aae/.mov sidecar files
      --undo LOGFILE       Undo a previous run using its log
  -q, --quiet / -v, --verbose
      --json               Machine-readable output
```

The tool runs as a dry run unless you pass `--apply`. Because of that, a mistyped command can't change anything.

**Template tokens:** `{date:<strftime>}`, `{seq}` (a counter for photos taken in the same second), `{camera}` (the camera model), `{orig}` (the original file name without extension) and `{ext}`.

## 3. Choosing the capture date

Check these sources in order and use the first valid one:
1. `EXIF:DateTimeOriginal` plus `OffsetTimeOriginal` and `SubSecTimeOriginal` if they're present
2. `EXIF:CreateDate` / `DateTimeDigitized`
3. `QuickTime:CreateDate` (for HEIC/MOV; note this value is stored in UTC)
4. `XMP:DateCreated`
5. The `--fallback` setting: the file's modified time, a date parsed from the file name (e.g. `IMG_20240714_183205`), or skip the file

A date counts as invalid if it's empty, `0000:00:00 00:00:00`, before 1990 or in the future. The source used for each file is reported in verbose and JSON output.

## 4. Libraries

| Option | Pros | Cons |
|---|---|---|
| **Python + `exiftool` (via PyExifTool)** | Reads almost every format, including HEIC and RAW; one batch process | Requires exiftool to be installed |
| Python + Pillow/piexif | Pure Python | Weak HEIC and RAW support |
| Go + `goexif` / Rust + `kamadak-exif` | Single binary | Patchy HEIC/CR3 support |

**Recommendation:** Python 3.10+ with `exiftool` as the main reader. Run it once in batch mode (`-stay_open`) so large folders stay fast. If exiftool isn't installed, fall back to Pillow for JPEG only and show a clear warning. Use `typer` or `argparse` for the CLI and package it with `pipx`.

## 5. Architecture

```
exifrename/
  cli.py          # argument parsing, output formatting
  scanner.py      # walk folders, filter by extension, group sidecars
  metadata.py     # ExifReader interface: ExiftoolReader, PillowReader
  dating.py       # date selection, validation, timezone shifting
  naming.py       # template rendering, name sanitizing
  planner.py      # build the full rename plan, resolve collisions
  executor.py     # apply the plan safely, write the undo log
  undo.py         # reverse a run from its log
```

**Data flow:** scan → read metadata in one batch → pick a date for each file → build the full rename plan → check the plan → show it (dry run) or apply it.

The key design rule is to **build the whole plan before renaming anything.** That lets the tool catch collisions and cycles up front.

## 6. Collisions and edge cases

- **Same-second photos (burst mode):** add a suffix, giving `…_18-32-05.jpg`, `…_18-32-05-01.jpg` and so on. Sort same-second files by subsecond time, then by original name, so the result is the same every run.
- **Target name already exists on disk** and isn't part of this run: add a suffix. Never overwrite.
- **Swaps and chains** (A→B while B→C): do a two-phase rename. First rename everything to temporary names (`.exifrename-tmp-<uuid>`), then to the final names.
- **Already-named files:** if a file already has its target name, leave it alone so re-running the tool changes nothing.
- **Sidecars and Live Photos:** files with the same base name (`IMG_1234.HEIC` + `IMG_1234.MOV` + `IMG_1234.xmp`/`.AAE`) are renamed together and share one base name.
- **Case-insensitive file systems** (Windows, macOS): treat `a.JPG` and `a.jpg` as the same name when checking collisions, and handle renames that only change case through a temporary name.
- **Unreadable or corrupt files:** report and skip them; one bad file doesn't stop the run.
- **Characters not allowed in file names:** clean up anything a template produces (`:`, `/`, `\`, `?` and so on), which matters especially on Windows.
- **Permission errors partway through a run:** stop, report what succeeded, and leave the undo log in a consistent state.

## 7. Safety and undo

- With `--apply`, the tool writes `.exifrename-log-<timestamp>.jsonl` in the target folder *before* each rename, as one `{old, new, status}` line per file. A crash then never leaves an unrecorded rename.
- `--undo LOGFILE` reverses the renames in reverse order and checks that each file still exists under its new name first.
- Exit codes: `0` success, `1` some files skipped or failed, `2` usage error, `3` dependency missing.

## 8. Example output

```
$ exifrename ~/Pictures/trip
DRY RUN: no files will be changed (use --apply)
  IMG_4021.JPG   → 2024-07-14_18-32-05.jpg      [DateTimeOriginal]
  IMG_4022.JPG   → 2024-07-14_18-32-05-01.jpg   [DateTimeOriginal]
  IMG_4023.HEIC  → 2024-07-14_19-01-44.heic     [DateTimeOriginal] (+ .MOV)
  scan_001.png   → SKIPPED                       [no date found]
3 to rename, 1 skipped, 0 errors
```

## 9. Testing

- **Unit tests:** date selection order, invalid-date rejection, template rendering, name cleanup, collision suffixes, and the order of the two-phase rename.
- **Fixture tests:** a small set of sample photos (JPEG with and without EXIF, HEIC+MOV pair, CR3, DNG, a burst series, a file with the zero date).
- **Property test** (Hypothesis): for any random plan, applying it and then undoing it restores the original file names exactly.
- **Platform tests:** run CI on Windows, macOS and Linux to cover case-insensitivity and illegal-character handling.
- **Performance check:** 10,000 files in under about 30 seconds with batch exiftool.

## 10. Milestones

1. **MVP:** JPEG only, Pillow reader, fixed name format, dry run and apply, collision suffixes.
2. **Robustness:** exiftool reader, HEIC/RAW support, fallback options, two-phase rename, undo log.
3. **Usability:** custom templates, sidecar grouping, `--tz-offset`, `--json`, recursive mode.
4. **Distribution:** pipx package, a standalone binary via PyInstaller, docs and man page.
5. **v2 ideas:** organizing into date folders, finding duplicates by content hash, watching a folder for new files.

## Open questions

- What should the default name format be? `2024-07-14_18-32-05` sorts correctly and works on every platform, but some people prefer `20240714_183205`.
- When `--fallback mtime` is on, should those files be marked in the name (e.g. a `~` prefix) so they can be spotted later?
- Should the undo log stay in the photo folder or go to a central place (`~/.local/state/exifrename/`)?
