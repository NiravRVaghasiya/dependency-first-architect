# Plan: `exifrename`, a CLI that renames photos by EXIF capture date

## 1. Goal and scope

**What it does:** It reads the capture timestamp from each photo in a folder and renames the file to a consistent, sortable name such as `2024-06-14_18-32-05.jpg`.

**Requirements:**
- It never loses or overwrites a file.
- It previews changes by default and only renames when you pass `--apply`.
- It writes an undo log, so you can reverse any run.
- It handles name collisions, missing EXIF data and companion files.

## 2. Technology

- **Language:** Python 3.10+. It runs on any OS and has good EXIF libraries.
- **EXIF reading:**
  - Default: **Pillow** for JPEG and TIFF, plus **pillow-heif** for HEIC/HEIF (iPhone photos).
  - Optional: shell out to **ExifTool** with `--backend exiftool` for RAW formats (CR2, NEF, ARW, DNG) and video. ExifTool is the most complete parser available.
- **CLI framework:** `argparse` (no extra dependency) or `typer` (nicer help text).
- **Packaging:** `pyproject.toml` with a console-script entry point, so users can install it with `pipx install exifrename`.

## 3. Command-line interface

```
exifrename PATH [options]

  --apply                 Actually rename (default is a dry-run preview)
  --format TEMPLATE       strftime template (default: "%Y-%m-%d_%H-%M-%S")
  --recursive, -r         Include subfolders
  --ext jpg,heic,...      Limit to these extensions (default: common image types)
  --fallback {skip,mtime} What to do if no EXIF date (default: skip)
  --shift "+1h30m"        Fix a camera clock that was set wrong
  --lowercase-ext         Normalize extensions (.JPG -> .jpg)
  --no-sidecars           Don't rename matching .xmp/.aae/.mov files
  --backend {pillow,exiftool}
  --log FILE              Where to write the undo log (default: inside PATH)
  --verbose / --quiet

exifrename undo LOGFILE   Reverse a previous run
```

## 4. Main logic

### 4.1 Find files
- List files and filter by extension, ignoring case.
- Skip hidden and system files (`.DS_Store`, `Thumbs.db`) and the tool's own log files.
- Sort the list so runs are repeatable.

### 4.2 Get the capture date
Try these sources in order and stop at the first one found:
1. `DateTimeOriginal` (tag 0x9003), the moment the shutter fired
2. `DateTimeDigitized` / `CreateDate` (0x9004)
3. `DateTime` (0x0132). This is often the edit time, so warn when it's used.
4. The file's modified time, only if `--fallback mtime` is set. Otherwise skip the file and report it.

Details to handle:
- EXIF stores dates as `YYYY:MM:DD HH:MM:SS`. Parse it strictly and reject placeholder values like `0000:00:00 00:00:00`.
- Read `SubSecTimeOriginal`, which helps separate burst shots.
- Read `OffsetTimeOriginal` if present. By default the name uses the local time the photo was taken, with no time-zone conversion.
- Apply `--shift` after parsing.

### 4.3 Build the new names
- Format the date with the template, then add the original extension (lowercased if `--lowercase-ext` is set).
- **Clean the filename.** Remove characters that are invalid on Windows (`: * ? " < > |`). This matters because the EXIF date format contains colons. Also block reserved Windows names such as `CON` and `NUL`.
- **Resolve collisions.** Several photos can share the same second (burst mode, multiple cameras):
  - First, add subseconds if available (`_123`).
  - Otherwise, add a counter: `_01`, `_02`, …
  - Check collisions against **both** the other planned names **and** files already in the folder that aren't part of this run.
  - Compare names ignoring case, because Windows and macOS file systems don't distinguish case (`A.JPG` and `a.jpg` are the same file).
- **Skip files that already have the right name**, so running the tool twice changes nothing.

### 4.4 Companion (sidecar) files
Group files that share a base name and rename them together:
- `IMG_1234.JPG`
- `IMG_1234.xmp` / `IMG_1234.JPG.xmp`
- `IMG_1234.AAE`
- `IMG_1234.MOV` (iPhone Live Photo)

The date comes from the main image only.

### 4.5 Rename safely
- **Rename in two steps.** First rename every file to a unique temporary name (`.exifrename-tmp-<uuid>`), then to its final name. This handles swaps and loops (A→B while B→A) without overwriting anything.
- Before any file is touched, write the undo log (JSON Lines: `{"old": ..., "new": ..., "tmp": ...}`). Update it as each rename finishes.
- If anything fails partway, stop and roll back the completed renames using the log.
- Never use a rename call that silently overwrites an existing file. Check that the target doesn't exist first.

### 4.6 Output
- **Dry run:** a table of `old name → new name` plus a summary (N to rename, N skipped for no date, N already correct, N collisions resolved).
- **Exit codes:** `0` for success, `1` if some files were skipped, `2` for an error or rollback.

## 5. Code layout

```
exifrename/
  cli.py          # argument parsing, output
  scan.py         # file discovery, sidecar grouping
  dates.py        # EXIF extraction, fallback order, parsing, shift
  backends/
    pillow_backend.py
    exiftool_backend.py
  planner.py      # builds the old->new mapping, collisions, cleaning
  executor.py     # two-step rename, undo log, rollback
  undo.py
tests/
```

Keep `planner.py` free of side effects: it takes a list of `(path, datetime)` pairs and returns a plan. That makes the trickiest logic easy to test without touching the disk.

## 6. Testing

- **Test images:** create small JPEGs during tests with `piexif`, setting exact date tags (including missing, invalid and duplicate timestamps).
- **Unit tests:**
  - Date fallback order and parsing edge cases
  - Collision suffixes and case-insensitive clashes
  - Cleaning invalid characters
  - `--shift` math, including crossing midnight or a month boundary
- **Integration tests** (using pytest's `tmp_path`):
  - Dry run changes nothing
  - `--apply` followed by `undo` restores the original state exactly
  - Swap and loop cases
  - Running twice gives the same result
  - Sidecar files follow their main image
- **CI:** run on Windows, macOS and Linux, since file-system behavior differs.

## 7. Milestones

1. **MVP:** JPEG only, Pillow backend, dry run and `--apply`, default format, counter suffixes.
2. **Safety:** two-step rename, undo log, the `undo` command, rollback on failure.
3. **Formats:** HEIC through pillow-heif, an optional ExifTool backend for RAW and video.
4. **Polish:** sidecar grouping, `--shift`, `--recursive`, custom templates, a nicer summary table.
5. **Release:** README with examples, publish to PyPI, pre-built binary through PyInstaller for users without Python.

## 8. Open questions

- **Time zones:** should names use the local capture time (simpler, matches what people expect) or convert to UTC (consistent across trips)? I suggest local time, with a `--utc` option.
- **Moving files:** should files ever be moved into date folders (`2024/06/`)? I suggest leaving that out of scope at first and adding it later as `--organize`.
- **Videos:** should they get first-class support, using QuickTime `CreationDate`, which needs ExifTool? Or only as Live Photo companions?
